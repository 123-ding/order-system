## 1. 引言

### 1.1 项目背景

随着低空经济快速发展，无人机在物流、巡检、应急救援等领域广泛应用，同时也带来了严峻的低空安全挑战。现有解决方案普遍存在以下问题：

- 各品牌无人机、探测、侦测、反制设备**协议不统一**，互联互通困难；
- 设备接入依赖厂商私有平台，**数据孤岛**严重；
- 缺乏统一的**可信认证**与**安全管控**能力；
- 运营人员需要同时操作多个平台，**效率低下**，易出现处置延误。

**低空智联网安全可信中台**旨在提供一个厂商无关、协议适配、统一管理的设备接入与管控平台，实现低空目标的感知、识别、管控与反制的全流程闭环。

### 1.2 目的

本文档用于：

1. 明确系统的功能性和非功能性需求；
2. 作为设计、开发、测试的基线文档；
3. 作为验收评审的依据。

### 1.3 范围

本文档覆盖低空智联网安全可信中台 Web 系统的全部需求，包括：

- 无人机、探测、侦测、反制四类设备的接入管理；
- 多协议适配层；
- 态势感知与可视化；
- 告警与事件管理；
- 安全可信管理；
- 系统管理与开放接口。

### 1.4 定义与缩略语

| 术语 | 说明 |
|------|------|
| UAV | 无人机（Unmanned Aerial Vehicle） |
| MAVLINK | 用于无人机通信的轻量级报文协议 |
| ADS-B | 广播式自动相关监视（Automatic Dependent Surveillance-Broadcast） |
| MQTT | 物联网轻量级消息协议 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| GIS | 地理信息系统（Geographic Information System） |
| TLS | 传输层安全协议（Transport Layer Security） |
| 中台 | 能力沉淀与复用的平台层，处于前台应用与后台系统之间 |

## 2. 总体描述

### 2.1 系统概述

低空智联网安全可信中台是一个 **B/S 架构的 Web 应用系统**，部署于本地或私有云。系统通过统一的协议适配层对接各品牌异构设备，向上提供统一的数据服务和管控界面。

```
┌─────────────────────────────────────────────────────────┐
│                    上层管理/指挥系统                        │
└─────────────────────┬───────────────────────────────────┘
                      │  北向 REST API / WebSocket
┌─────────────────────▼───────────────────────────────────┐
│              低空智联网安全可信中台（本系统）                  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  │  无人机   │ │  探测设备 │ │  侦测设备 │ │  反制设备 │   │
│  │  管理模块 │ │  管理模块 │ │  管理模块 │ │  管理模块 │   │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘   │
│       └─────────────┴───────────┴─────────────┘          │
│                   协议适配层                               │
└──────┬──────────────┬───────────┬──────────────┬─────────┘
       │              │           │              │
  MAVLINK/        TCP/UDP      MQTT/WS       TCP/串口
  DJI SDK         ONVIF        HTTP          自定义
       │              │           │              │
  ┌────▼──┐     ┌─────▼──┐  ┌────▼──┐     ┌────▼──┐
  │各品牌  │     │探测设备 │  │侦测设备│     │反制设备│
  │无人机  │     │        │  │       │     │       │
  └───────┘     └────────┘  └───────┘     └───────┘
```

### 2.2 用户角色

| 角色 | 说明 |
|------|------|
| 系统管理员 | 负责系统配置、用户管理、权限分配 |
| 设备管理员 | 负责设备注册、协议配置、设备维护 |
| 操作员 | 日常监控、告警处置、任务下发 |
| 审计员 | 查看审计日志，不可操作设备 |
| API 集成方 | 通过北向接口获取数据的第三方系统 |

### 2.3 运行环境

**服务端：**
- OS：Linux（Ubuntu 20.04+ / CentOS 7+）
- Node.js >= 18.0 或 Java 17+
- MySQL 8.0+ / PostgreSQL 14+
- Redis 6.0+
- Nginx（反向代理）

**客户端：**
- 现代浏览器：Chrome 90+、Firefox 88+、Edge 90+
- 分辨率：建议 1920×1080 及以上

## 3. 功能需求

### 3.1 设备接入管理

#### 3.1.1 设备注册（通用流程）

**用例描述：** 操作人员通过 Web 表单注册一台新设备。

**前置条件：** 用户已登录，具有设备管理权限。

**主流程：**
1. 用户进入对应设备类型的管理页面（无人机/探测/侦测/反制）；
2. 点击"新增设备"按钮；
3. 填写设备基本信息：
   - 设备名称（必填）
   - 设备品牌（下拉选择，如：大疆/道通/极飞/自定义…）
   - 设备型号（文本输入）
   - 所属区域（下拉选择）
4. 配置通信参数：
   - **通信协议**（下拉选择，根据设备类型动态加载可用协议列表）
   - **IP 地址**（输入框，支持格式校验）
   - **端口**（输入框，数字，1-65535）
   - 根据协议类型动态显示附加参数（如 MQTT 需填 Topic、用户名/密码）
5. 点击"测试连接"验证连通性；
6. 保存设备信息；
7. 系统显示注册成功提示，设备出现在设备列表中。

**异常流程：**
- 3a. 设备名称重复：提示"设备名称已存在，请修改"；
- 5a. 连接测试失败：提示具体错误（超时/拒绝连接/认证失败），允许继续保存（离线状态）；
- 6a. 保存失败：提示错误原因，表单数据保留。

#### 3.1.2 协议选择需求

各设备类型支持的协议如下：

| 设备类型 | 可选协议 |
|----------|----------|
| 无人机 | MAVLINK 1.0、MAVLINK 2.0、DJI Mobile SDK、DJI MSDK、自定义 TCP、自定义 UDP |
| 探测设备 | TCP（自定义）、UDP（自定义）、串口 RS-232、串口 RS-485、ONVIF、ADS-B（1090MHz）、自定义 HTTP |
| 侦测设备 | WebSocket、MQTT、HTTP/REST、自定义 TCP、自定义 UDP |
| 反制设备 | TCP（自定义）、UDP（自定义）、串口 RS-232、MQTT、自定义协议 |

当用户选择不同协议时，IP/端口等参数区域自动显示/隐藏相应配置项：
- **TCP/UDP 协议**：显示 IP 地址、端口
- **串口协议**：显示串口号（COM1/ttyUSB0 等）、波特率、数据位、停止位、校验位
- **MQTT 协议**：显示 Broker IP、端口、Topic、客户端 ID、用户名、密码
- **HTTP/REST 协议**：显示 Base URL、API Key/Token
- **WebSocket 协议**：显示 WS URL、认证 Token

#### 3.1.3 设备列表与管理

**需求：**
- 以表格形式展示设备列表，支持按名称、品牌、状态、区域筛选；
- 列表字段：设备名称、品牌、型号、协议、IP/连接地址、在线状态、最后心跳时间、操作（编辑/删除/详情）；
- 支持批量启用/禁用设备；
- 支持单台设备的连接测试。

### 3.2 协议适配层

**FR-3.2.1** 系统内置以下协议解析器：
- MAVLINK 协议解析器（支持 v1.0/v2.0）
- DJI 数据协议解析器
- ONVIF 协议适配器
- MQTT 客户端
- TCP/UDP 通用客户端（支持自定义字节帧解析规则）
- 串口通信适配器

**FR-3.2.2** 协议插件化：支持通过上传协议插件包扩展新协议，无需重启服务。

**FR-3.2.3** 数据标准化：所有接入设备的数据统一转换为平台内部标准数据格式后存储和分发。

### 3.3 态势感知

**FR-3.3.1** 地图展示：
- 基于 Leaflet + OpenStreetMap 或天地图展示实时地图；
- 支持设备图标覆盖、轨迹线绘制；
- 支持地图图层切换（标准图/卫星图/地形图）。

**FR-3.3.2** Dashboard：
- 实时显示各类设备在线总数/告警数；
- 显示最近 10 条告警；
- 显示设备接入趋势折线图（24 小时）。

### 3.4 告警管理

**FR-3.4.1** 告警实时推送：系统通过 WebSocket 将告警事件实时推送到已登录的前端页面，延迟 ≤ 2 秒。

**FR-3.4.2** 告警级别：
- **红色（紧急）**：禁飞区入侵、反制设备故障；
- **橙色（严重）**：探测到未识别目标、设备通信中断（> 30 秒）；
- **黄色（预警）**：设备电量低、信号弱。

**FR-3.4.3** 告警处置：操作员可对告警进行确认（Acknowledge）、指定处置方案、关闭处理，每次操作须填写备注。

### 3.5 安全可信需求

**FR-3.5.1** 身份认证：系统登录支持用户名/密码 + TOTP 双因素认证。

**FR-3.5.2** 会话管理：JWT Token，有效期 8 小时，支持主动注销。

**FR-3.5.3** 传输安全：生产环境强制 HTTPS（TLS 1.2+）。

**FR-3.5.4** 设备可信：支持为设备配置 X.509 证书，实现双向 TLS 认证。

**FR-3.5.5** 操作审计：所有增删改操作、告警处置、指令下发操作均记录操作人、时间、内容，不可修改。

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 并发接入设备数 | 支持同时接入 ≥ 500 台设备 |
| 数据处理延迟 | 设备数据从接收到展示 ≤ 500ms |
| 页面响应时间 | 普通列表页面首屏加载 ≤ 2 秒 |
| 告警推送延迟 | 告警触发到前端展示 ≤ 2 秒 |
| 系统可用性 | ≥ 99.9%（年停机时间 ≤ 8.76 小时） |

### 4.2 安全需求

| 指标 | 要求 |
|------|------|
| 认证方式 | 用户名/密码 + 可选双因素认证（TOTP） |
| 密码策略 | 长度 ≥ 8 位，含大写字母、数字、特殊字符 |
| 登录失败锁定 | 连续 5 次失败后锁定账号 15 分钟 |
| 会话超时 | 无操作 30 分钟自动退出 |
| 数据加密 | 传输层 TLS 1.2+，存储敏感数据 AES-256 加密 |
| 漏洞扫描 | 上线前通过 OWASP Top 10 安全扫描 |

### 4.3 可靠性需求

- 关键服务（协议适配、告警推送）支持进程守护与自动重启；
- 数据库每日自动备份；
- 支持主备部署模式。

### 4.4 可扩展性需求

- 协议适配层插件化，新协议无需修改核心代码；
- 设备类型可通过配置文件扩展；
- 前端组件化设计，新设备类型页面复用通用表单组件。

### 4.5 易用性需求

- 新用户在无培训情况下，注册一台设备的操作时间 ≤ 5 分钟；
- 关键操作（删除设备、下发反制指令）需二次确认；
- 表单字段提供说明提示（Tooltip）；
- 支持中文界面（简体中文为主，预留国际化扩展）。

## 5. 约束条件

1. **浏览器兼容**：仅需兼容 Chrome 90+、Firefox 88+、Edge 90+，不需要支持 IE；
2. **网络环境**：系统部署在专网/本地内网，可不依赖公网连接；
3. **法律合规**：反制设备操作须遵守无线电管理法规，系统需提供操作授权流程；
4. **开发语言**：前端 Vue 3 + TypeScript，后端 Node.js（Express）或 Java（Spring Boot），均可。
